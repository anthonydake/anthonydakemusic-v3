# CLAUDE.md — anthonydakemusic-v3

## Project Overview

Personal website for Anthony Dake — drummer, session musician, music director based in Columbus, OH. Built with Next.js 16 (App Router, Turbopack) + Tailwind CSS v4, deployed on Vercel (auto-deploy on push to `main`).

**Production**: https://www.anthonydakemusic.com
**Repo**: https://github.com/anthonydake/anthonydakemusic-v3
**Hosting**: Vercel project `anthonydakemusic-v3` (auto-deploy on push to main)

## Architecture

Next.js App Router. Every public route uses the `page.tsx` (server, exports `metadata`) + `page.client.tsx` (`"use client"`) split. No server components render UI — all UI lives in the client files.

### Pages (routes under `app/`)

- `/` — Home. Three-section snap-scroll (`hero → services → epk`) rendered by `HomeClient.tsx`. Inline header lives here, not `SiteHeader`.
- `/about` — Bio/story: church drummer → DCI/WGI → conservatory → rebuild. Testimonials component mounted below the article (renders nothing until `data/testimonials.data.ts` is populated).
- `/epk` — Electronic Press Kit. Resume download, YouTube demo reel, booking contact.
- `/placements` — Record credits index (artwork grid). Data from `data/projects.data.ts`.
- `/performance` — Live performance credits index. Data from `data/performance.data.ts`.
- `/practice` — "Open Practice Room". Reverse-chronological practice log with per-day groups, search, and optional video clips. Data from `data/practice.data.ts`.
- `/practice/feed.xml` — RSS feed of practice entries (dynamic route).
- `/admin/archive` — Password-gated admin page listing captured archive emails.
- `/not-found.tsx` — Custom 404 (uses `SiteHeader`).
- `/robots.txt`, `/sitemap.xml` — generated by `app/robots.ts` and `app/sitemap.ts`.

### API routes (`app/api/`)

- `POST /api/book` — Booking form submission. Writes to Neon Postgres (`bookings`) + adds email to `archive_emails`. Origin check, honeypot, ISO-date validation, fire-and-forget Resend notification.
- `POST /api/archive` — Email capture (writes `archive_emails`).
- `POST /api/archive/auth` — Password check for the admin page. Sets `archive_admin` httpOnly cookie (10 min).
- `GET /api/archive/list` — Returns archived emails (requires the auth cookie).

### Key Components (`app/components/`)

- `HomeClient.tsx` — The three-section snap-scroll home: hero (logo + proof strip + EPK CTA + socials), services (2 cards + placements strip + `AudioShowcase`), epk (closing panel). Custom wheel/touch snap logic + IntersectionObserver on `[data-snap-section]`.
- `AudioShowcase.tsx` — Horizontal row of circular play/pause buttons with a progress ring. Renders `null` while `AUDIO_CLIPS` is empty.
- `BookingModal.tsx` — Booking inquiry dialog. Focus trap, Esc-to-close, honeypot, body-scroll lock, auto-close on success.
- `SiteHeader.tsx` — Shared header for every subpage. Symmetric 3-column grid (Placements/Performance · HomeMark · Practice/About + Book CTA). Mobile hamburger overlay. Owns its own `BookingModal` state.
- `HomeMark.tsx` — 🥁 glyph used as the home logo in both headers.
- `LogoArchitectOfSound.tsx` — Centered type lockup (uses `next/image` for the portrait), with hover scramble.
- `TextScramble.tsx` — Animated glyph-scramble primitive used by the proof strip and the logo.
- `JsonLd.tsx` — `<script type="application/ld+json">` helper.
- `TransitionProvider.tsx` — Curtain/fade page transitions. Exposes `useTransition()` with `triggerTransition`, `isTransitioning`, `prefersReducedMotion`, `isMobileFallback`.
- `CurtainOverlay.tsx` — The overlay element driven by `TransitionProvider`.
- `Testimonials.tsx` — Editorial pull-quote block on About. Renders `null` while `testimonials` is empty.

There is **no site-wide footer** (removed in `08c3b27`). `ColumbusTime.tsx` and `SiteFooter.tsx` no longer exist. The mobile `FloatingCards`, `CustomCursor`, `LenisProvider`, `ArchiveModal`, `ScribbleLink`, `ScrambleText` components mentioned in older docs are also gone.

## Home Page Anatomy

`app/page.client.tsx` is a thin wrapper that owns the inline header + `BookingModal` state. The three snap sections are rendered inside `HomeClient.tsx`:

1. **hero** (`data-id="hero"`) — `LogoArchitectOfSound`, scrambled proof strip (`~405 performances · ~52 placements`), EPK CTA pill, social-icon row. Can be overlaid with a background reel when `HERO_VIDEO_URL` is set.
2. **services** (`data-id="services"`) — `(02) — services` eyebrow, `<AudioShowcase />`, two `ServiceCard`s (Live Performance, Session Drums) wired to `onOpenBooking`, and a "Recent — index of N" placements strip linking to `/placements`.
3. **epk** (`data-id="epk"`) — Closing booking panel + EPK CTA.

Routing: `HomeClient` accepts `initialSection?: "hero" | "services" | "epk"` and will scroll to the matching ref on mount. The section-id union is a **closed type** — adding a fourth value is a breaking change throughout the file.

Snap mechanics: `useLayoutEffect` sets `scrollTop` to the target section on mount. On desktop a `wheel` listener (prevents default + animates to the next section's `offsetTop`) and a `touchend` listener handle snapping. On mobile (`isMobileFallback`) the home swipes up to `nextHref` via `triggerTransition`. An IntersectionObserver with `threshold: [0.55, 0.8]` flips the per-section `visible` state that drives the fade-in.

## Booking System

- UI: `BookingModal.tsx` opened from the Book → button in `SiteHeader.tsx` (subpages), `app/page.client.tsx` (home-page inline header), and the two service cards in `HomeClient.tsx` (passed via `onOpenBooking`). The modal state is **duplicated** in both headers; see Gotcha 7.
- Fields: `name` (required), `email` (required, regex-validated), `eventDate` (optional, `type="date"`, `min={todayIso}`, ISO-validated on the server), `eventType` (required, select), `message` (optional). Hidden honeypot `website` field.
- Endpoint: `POST /api/book`.
  - Origin check: rejects POSTs whose `Origin` host does not match `NEXT_PUBLIC_SITE_URL`.
  - Honeypot: if `body.website` is non-empty, the route returns `{ ok: true }` without writing — bots think it worked, no retry.
  - Validation: trims strings, lowercases email, validates email regex, validates date as `YYYY-MM-DD`.
  - Storage: `bookings` table (Neon Postgres via `@vercel/postgres`). Idempotent `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE … ADD COLUMN IF NOT EXISTS` on every request (schema evolves without migrations). Also upserts the email into `archive_emails`.
  - Notification: fire-and-forget Resend POST (`notifyBooking`). Never blocks the response. Falls back to `console.warn` when `RESEND_API_KEY` is missing.
- DB provider: **Neon Postgres** provisioned through the Vercel Neon marketplace integration. Uses `POSTGRES_URL` / `POSTGRES_URL_NON_POOLING` etc. injected by Vercel.
- Env vars used:
  - `POSTGRES_URL` (+ friends) — Neon connection, auto-provisioned.
  - `NEXT_PUBLIC_SITE_URL` — origin-check target.
  - `BOOKING_NOTIFY_EMAIL` — recipient of notification (default `adakemusic@gmail.com`).
  - `BOOKING_NOTIFY_FROM` — notification From address (default `noreply@anthonydakemusic.com`).
  - `RESEND_API_KEY` — injected automatically by the **Resend native integration** from the Vercel Marketplace (resource `resend-email-apricot-harbor`, Free plan, Production + Preview, marked Sensitive). Never set it by hand; manage it from Vercel → Integrations → Resend.
  - `RESEND_EMAIL_DOMAIN` — also injected by the integration (`anthonydakemusic.com`). The domain is **not verified yet**: DNS for anthonydakemusic.com is on Cloudflare, and the DKIM TXT + `rsend`/`send` CNAMEs listed at resend.com/domains still need to be added there.
  - `BOOKING_NOTIFY_FROM` — currently `onboarding@resend.dev` (Resend's test sender, set 2026-11-03). It only delivers to the Resend account owner (adakemusic@gmail.com), which is fine for notifications. Switch to `noreply@anthonydakemusic.com` once the domain is verified.
  - `ARCHIVE_ADMIN_PASSWORD` — for `/admin/archive` auth.
- Verified 2026-11-03: a test POST to `/api/book` produced a "Delivered" email in the Resend log (subject `New booking inquiry — <type> (<name>)`). Resend's email log at resend.com/emails is the first place to look if notifications stop.

### To activate the hero reel

```bash
npx vercel env pull .env.local           # once, to get BLOB_READ_WRITE_TOKEN
npm run upload-media -- ./media/reel.mp4 hero/reel.mp4
```

The script prints a line to paste into `app/components/HomeClient.tsx`:

```ts
const HERO_VIDEO_URL: string | null = "https://…/hero/reel.mp4";
```

Recommended specs: H.264 MP4, 1920×1080 (or a 1080×1920-safe crop), 8–15s seamless loop, muted, ≤ ~6MB. Posters fall back to `/anthony-dake-drums.jpg`.

### To activate `AudioShowcase`

```bash
npm run upload-media -- ./media/gospel.mp3 audio/gospel.mp3
```

The script prints an entry to paste into `AUDIO_CLIPS` in `app/components/AudioShowcase.tsx`:

```ts
{ id: "gospel", label: "Gospel", src: "https://…/audio/gospel.mp3" },
```

Recommended specs: MP3 ~128 kbps, 20–30s, loudness around −14 LUFS, clean fade-in/fade-out (no tail noise).

Edit `data/testimonials.data.ts` — add real entries only, with written permission. The About page's `<Testimonials />` renders nothing until the array has at least one item (first 3 are displayed).

## Critical Gotchas

### 1. HOME PAGE HAS ITS OWN INLINE HEADER
`app/page.client.tsx` renders its own header (hamburger, nav, HomeMark pill, Book CTA) — it does NOT use `SiteHeader.tsx`. This is because the home page couples navigation/scroll behavior to the header. When changing header markup (nav items, Book CTA styling, skip-to-content, mobile overlay), update BOTH files:
- `app/components/SiteHeader.tsx` (all subpages + 404)
- `app/page.client.tsx` (home page)

### 2. GRADIENT TEXT SYSTEM — BARE TEXT IN DIVS IS INVISIBLE
`globals.css` sets `body { color: transparent; background-clip: text }` with the gradient painted onto leaf elements (`p`, `span`, `a`, `h1`–`h6`, `button`, etc.). Container elements (`div`, `section`, `main`, `header`, `nav`, `article`, `form`) get `background-image: none !important`, so any text placed **directly** in a `<div>` renders invisible. Always wrap visible text in `<span>`, `<p>`, `<a>`, `<label>`, or a `<button>` label.

### 3. JSX `.map()` PATTERN
Don't use a ternary inside a parenthesized arrow return inside `.map()`. Use the if/return pattern:
```jsx
items.map((p) => {
  const Row = (<>…</>);
  if (p.url) return <a key={p.id}>{Row}</a>;
  return <div key={p.id}>{Row}</div>;
})
```

### 4. SKIP-TO-CONTENT LINK
Both headers render `<a href="#main-content" className="skip-to-content">`. The styles live in `globals.css` under `.skip-to-content` + `.skip-to-content:focus` — the class manually strips the gradient text-fill and uses `clip-path: inset(50%)` + `opacity: 0`. Do NOT swap it for Tailwind's `sr-only`; the gradient cascade interferes.

### 5. TYPESCRIPT TIMERS
`window.setInterval` returns `number`, but `ReturnType<typeof setInterval>` resolves to `NodeJS.Timeout`. Type timer IDs explicitly: `let intervalId: number | null = null`.

### 6. VIEWPORT + SAFE AREAS
`app/layout.tsx` ships `viewport-fit=cover` so `env(safe-area-inset-*)` is available on iOS. Safe-area padding is applied inline per-component (practice page modal, main-content wrappers) — there is no global rule for it.

### 7. BOOKING MODAL STATE IS DUPLICATED
Both `SiteHeader.tsx` and `app/page.client.tsx` keep their own `bookingOpen` state and render their own `<BookingModal />`. Only one header is ever mounted at a time, so there is no conflict — but when you add a new entry point (another component with a Book button), either pass an `onOpenBooking` callback up (as `HomeClient` does) or own another `useState` locally. There is no shared context.

### 8. GRADIENT TEXT + FORM CONTROLS
`<input>`, `<textarea>`, `<select>`, `<option>` need explicit `color` / `-webkit-text-fill-color` or the gradient-text cascade makes their values invisible. Use the `.form-input` class in `globals.css` (sets `color: #f5f5f5 !important` + kills the gradient). The booking modal headings/labels use `.modal-plain`, `.modal-label`, `.modal-error` for the same reason.

### 9. ASSET-GATED FEATURES — EMPTY IS CORRECT
Three features render **nothing** in production when their data is empty:
- `HERO_VIDEO_URL` (`HomeClient.tsx`) — `null` → no reel, no overlay, no extra DOM.
- `AUDIO_CLIPS` (`AudioShowcase.tsx`) — empty → component returns `null`.
- `testimonials` (`data/testimonials.data.ts`) — empty → `<Testimonials />` returns `null`.

Replace them with real assets/quotes; do not invent new placeholder content, and do not "clean up" by emptying them unless Anthony asks. The source placeholder files are in `~/Claude-Workspace/4-architect/media-placeholders/`.

### 10. CLOSED SECTION-ID UNION
`HomeClient`'s `initialSection` and the internal `visible` state both use the type `"hero" | "services" | "epk"`. The IntersectionObserver callback casts `data-id` to this type. Adding a new snap section means updating the type, the state shape, the observer cast, and the refs in one pass.
